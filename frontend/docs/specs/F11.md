# F11: Revisão final de qualidade

- Fase: F11
- Data: 2026-11-16
- Depende de: F01 a F10
- Natureza: revisão, medição e correção. Nenhuma funcionalidade nova.

## Objetivo

Fechar o front-end com portões automáticos de qualidade, medições reproduzíveis e correções pontuais de acessibilidade, responsividade, i18n, segurança, desempenho, testes e observabilidade. O backend e qualquer arquivo fora de `frontend/` permanecem intocados.

## Portões de qualidade

1. `npm run check` executa lint, typecheck, testes unitários, portões de conteúdo e build de produção.
2. `npm run check:content` falha quando:
   - falta chave em `pt`, `es` ou `en`, ou existe locale fora de `pt`, `es`, `en`;
   - há texto visível fixo fora do dicionário em JSX (nó de texto ou atributo textual);
   - há termo proibido de dado fictício (`mock`, `fixture`, `faker`, `lorem`, nomes do protótipo) em código de produção;
   - há travessão longo em código, testes ou documentação.
3. A varredura de dados fictícios ignora testes automatizados e documentação, onde termos como `mock` descrevem a estratégia de teste.
4. `npm run check:security` falha quando há `dangerouslySetInnerHTML`, token de sessão em storage acessível ao JavaScript, `localStorage`/`sessionStorage` com credencial ou `console.log` esquecido em código de produção.
5. `npm run analyze` mede o tamanho dos chunks do build e falha acima do orçamento definido.

## Acessibilidade

1. Matriz axe em todas as rotas, nos temas claro e escuro e nos idiomas pt, es e en, com backend de teste local, sem depender de dados reais.
2. Passagem somente por teclado nas rotas principais, com verificação de foco visível e ordem de foco.
3. Rótulos ARIA verificados pelo axe e pelos testes de navegação.
4. Contraste AA coberto pelo axe nos dois temas.
5. `prefers-reduced-motion` emulado e verificado.

## Responsivo

1. Larguras 360, 768, 1280 e 1920 px em cada rota.
2. `document.documentElement.scrollWidth` não pode exceder `clientWidth`.
3. A régua de risco deve renderizar os 101 pontos e permanecer inteira, sem rolagem horizontal, inclusive no mobile.

## Segurança

1. Cabeçalhos: CSP, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`, `X-Frame-Options`, `Permissions-Policy` e HSTS em HTTPS.
2. Cookies de sessão `HttpOnly`, `Secure` em HTTPS, `SameSite=Lax` e sem token acessível ao JavaScript.
3. Nenhum HTML de API renderizado com `dangerouslySetInnerHTML`; textos de API são texto simples.
4. 401 redireciona para login, 403 mostra acesso negado e 429 respeita `Retry-After` com aviso amigável traduzido.
5. `npm audit` sem vulnerabilidades críticas.

## Desempenho

1. Visualizador de documento e gráficos carregados sob demanda.
2. Imagens com `next/image` ou SVG local; nenhuma imagem remota sem otimização.
3. Relatório Lighthouse acima de 90 em desempenho, acessibilidade e boas práticas na landing e no painel.
4. Relatório de bundle anexado em `docs/QUALITY.md`.

## Testes

1. Suíte e2e dos fluxos críticos: login, upload e dossiê, filtros, notificações e conta.
2. Screenshots de regressão visual nos dois temas para landing e painel.
3. Suítes existentes continuam verdes.

## Observabilidade

1. Integração opcional por `NEXT_PUBLIC_SENTRY_DSN`, carregada apenas quando configurada.
2. Nenhuma PII, token, conteúdo de documento ou payload de API é enviado.
3. Sanitização testada por unidade.

## Critérios de aceite

- `npm run check` verde.
- `npm run check:content` e `npm run check:security` com zero ocorrências.
- `npm audit` sem críticas.
- `docs/QUALITY.md` com resumo de axe, Lighthouse, bundle e responsividade.
- `README.md` com como rodar, testar e implantar na Vercel.
- `PROGRESS.md` final atualizado.
- Nenhum arquivo fora de `frontend/` alterado.
